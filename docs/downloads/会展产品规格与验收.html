序场会展：产品规格与验收

版本 2.0 · 2026-10-02 · 体验交互样品

依据 电鸭公开摘要制作。公开需求偏向低保真研发原型；本次在交互基础上完善视觉，用于展示产品思路。下文“已实现”均指本机浏览器样品，生产建议尚未实现服务端能力。

1. 目标与流程

让运营人员从活动准备走到报名、入场与统计，同时让参会者看到主题、议程、报名表与凭证。原型覆盖前后两个视角，可用来讨论具体迭代。

草稿与资料票种与议程发布与报名参会凭证名单与签到记录与沟通

2. 页面与规则

页面本机已实现规则
活动工作台草稿创建、发布、资料编辑、活动切换、四项准备清单日期顺序正确；容量为正整数且不得低于有效报名；新日期必须包含已有议程
报名配置姓名必填；单位和手机号可开关；保存配置；手工与完整报名预览草稿禁止报名；关闭字段保留历史数据
票种与名额新建、编辑免费票种，查看独立名额使用有效报名不能超过票种和活动容量；票种名额不得低于已有报名人数
议程与嘉宾新增和编辑日期、时间、主题、主讲人与会场日期在活动范围内；结束晚于开始；同日期同会场不得重叠
报名名单搜索、状态/票种筛选、10 条分页、选择、批量签到、取消、导出、凭证取消保留记录并释放名额；取消人员不可签到
现场签到编号/手机号精确查找、姓名包含查找、签到、最近签到、撤销重复签到禁用；撤销需原因并写操作记录；同名须人工确认
展位管理固定 8 展位图示、分配、编辑、释放与导出必填参展单位、联系人与有效手机号；释放后为待分配
数据与记录有效人数、到场、票种、单位、报名日期和操作记录取消不占名额，不计有效报名；日志仅展示当前活动，最多保存最近 200 条全工作空间记录
沟通草稿确认/提醒/变更，全部有效或未签到受众，生成与下载不发送邮件、短信或其他消息

3. 数据对象

对象主要字段与关系生产研发建议
Eventid、name、start/end、location、capacity、status、fields、category、description；包含 tickets、agenda 和 booths加 tenant_id、负责人、时区、报名窗口与编辑版本
Ticketid、name、capacity；从属于 Event本样品为免费票；交易型票种需要费用、销售时间和独立订单模型
Sessionid、date、start/end、name、speaker、room统一会场标识，服务端校验时间冲突和活动日期
Registrationid、event、name、company、phone、ticket、status、checked、at、submitted服务端生成编号，原子校验名额，幂等提交；严格租户与活动隔离
Booth固定 code → company、contact、phone真实图纸和展位目录由运营提供；并发编辑需版本控制
OperationLogid、event、text、time；本机最近 200 条加操作员、对象、前后值、原因；日志只追加并配置保留周期

4. 状态与例外

活动：draft → published。报名：active → cancelled，取消释放名额并保留原记录。签到：待签到 → 已签到，撤销需原因并生成记录。取消时清除当前签到状态；此前操作仍在日志中。已取消的手机号可以重新报名，产生新的独立报名编号。

票种总名额允许高于活动总容量，实际报名同时受两者约束；没有票种删除或议程删除入口。允许提前演示签到，不校验正式入场时间。凭证为本机文本示例，不是联网电子票或二维码。

5. 生产角色与接口建议

角色权限建议
团队管理员成员、权限、租户配置及活动管理
活动运营负责活动的资料、报名、票种、议程、展位和导出
签到员仅查找与签到必要字段，禁止导出完整联系资料；撤销权限单独配置
参会者提交和查看自己的报名与凭证

接口可按活动、票种、议程、报名、签到/撤销、展位与日志拆分。服务端需要租户鉴权、统一错误码、分页、编辑版本、原子容量校验与签到幂等。支付与退款不应复用本机的“取消报名”动作代替真实账务处理。

6. 验收用例

编号动作预期
P01新建草稿、发布、配置可选字段、报名并刷新状态和记录保留；关掉单位后新表单不出现单位
P02活动容量 1，尝试第二次报名阻止超过活动容量

7. 现有边界与后续确认

仅 localStorage 保存，没有后端、真实公开报名 URL、登录、角色鉴权、商户支付、短信邮件、摄像头扫码、打印硬件或多设备同步。统计为虚构样品数据，不宜用于真实活动收集个人信息。

接单后确认：优先活动类型、免费/审核/付费模式、报名时间规则、签到设备与离线需求、多租户权限、场馆图纸、展位交易，以及客户既有接口。首个合同建议只覆盖一个具体迭代。
